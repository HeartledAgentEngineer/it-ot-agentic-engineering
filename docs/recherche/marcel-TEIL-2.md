## Top-Regeln aus meinem Bereich

**(aus den 5 Marcel-Blöcken der Positionen 9–16)**

1. **Zwei Rollen, zwei Modelle — nie alles mit einem.** Der Planer/Architekt erstellt den Plan, der Arbeiter führt ihn Schritt für Schritt aus. Ein Modell für Plan *und* Umsetzung verbrennt Tokens und verschenkt den Zweit-Modell-Vorteil. *(Pos. 11, 13:26)*
2. **Der Planer stellt erst Rückfragen, dann wird gebaut.** Ein Rückfragen-Skill („Grill-Me") klopft Stack, Datenmodell, State, Persistenz, Teststrategie und Responsive-Ziel ab; die Antworten sind der Bauvertrag. *(Pos. 11, 09:38)*
3. **TDD ist der Übergabe-Vertrag:** Tests zuerst, sie müssen rot sein; der Arbeiter arbeitet sie auf grün. Danach validiert der Planer und startet bei Abweichung eine Revisionsschleife. *(Pos. 11, 08:28)*
4. **Verifikation gehört zum Auftrag, nicht in die Nachbesserung.** Der Agent testet selbst end-to-end im Browser — jede Form, jeden Button, jeden Link, alle Breakpoints. *(Pos. 11, 12:54; Pos. 15, 18:01/20:30)*
5. **Vorher/Nachher belegen.** Ausgangszustand festhalten und das Ergebnis als Side-by-Side-Vergleich vorlegen; ohne das ist „besser" eine Behauptung. *(Pos. 15, 17:10/18:38)*
6. **Benchmark nur mit identischem Input in leeren Verzeichnissen.** Gleicher Prompt, gleiche Aufgabe, frisches Verzeichnis pro Kandidat — sonst ist der Vergleich wertlos. *(Pos. 10, 13:01)*
7. **Harte Metriken erheben: Dauer, Tokens, Kosten, Ergebnisqualität.** Das schnellere Modell war das teurere — Preis und Zeit getrennt lesen. *(Pos. 9, 19:37/20:03/25:19)*
8. **Scope-Treue ist ein Bewertungskriterium erster Klasse.** Wer „Hero Section" beauftragt, will nicht die halbe Seite — das Modell, das die Grenze hält, gewinnt. *(Pos. 10, 16:48)*
9. **Effort-Level an Aufgabengröße koppeln.** Hoher Effort schaltet mehrere parallel arbeitende Agenten frei — nur bei umfangreichen Aufgaben sinnvoll. *(Pos. 12, 09:33; Pos. 15, 17:43)*
10. **Bestehender Code ist die Kontextquelle.** Design-Tokens und Komponenten aus dem Repository ziehen lassen (Monorepo mitdenken), nicht aus Screenshots oder Browser-Klicks. *(Pos. 12, 11:29/12:05; Pos. 15, 19:02)*
11. **Prompt nach Schema:** XML-Tags für die Persona, explizite „required Skills" — Prompt-Erstellung selbst delegieren und gegen Best Practice prüfen lassen. *(Pos. 15, 17:24)*
12. **Meilensteine in Issues zerlegen und im Prompt referenzieren** (Epic/Umbrella Issue → Unteraufgaben), damit der Agent eine adressierbare Spur hinterlässt. *(Pos. 12, 08:52/10:01)*
13. **Teamkonventionen ins Projektwissen schreiben.** Sonst schlägt das Modell seinen eigenen Standard vor (Vite statt Next.js, Context statt Zustand) und man korrigiert jede Runde neu. *(Pos. 11, 10:08)*
14. **Output-Format explizit spezifizieren** (Text / Zahl / Datum / Boolean / Liste) — unbestimmt heißt Fließtext. *(Pos. 9, 23:30)*
15. **Was nicht im Prompt steht, wird nicht gemacht.** Anforderungen explizit machen; freundliche Extras des Agenten sind ein Bonus, nicht planbar (Docs blieben bewusst deutsch). *(Pos. 15, 20:22)*
